# IPsec（Security Architecture for IP）
* 概要・用語
  * 暗号化によりIP（ネットワーク層）でのデータのやりとりの安全性を高めるセキュリティアーキテクチャ
  * SP（Security Policy）
    * IPSecルータが、通信相手のIPSecルータにパケットを送信時、IPSecを使うか否か/使うならどのSAを使うか選択するかといったルール（引用： [NW_H28_PM2_問2](https://www.ipa.go.jp/shiken/mondai-kaiotu/gmcbt8000000g6fw-att/2016h28a_nw_pm2_qs.pdf)のp14〜16
    * 通信に対して、3つのアクションを選択する
      * Protect：IPSecを使う
      * Bypass：IPSecを使わず、暗号化せずにルーティングする
      * Discard：パケットを破棄する
    * SPD（SP Database）
      * IPアドレス、プロトコル(TCP/UDP/ICMP等)、TCPポートといった情報に応じて、Protect/Bypass/Discardを決定するためのDB
      * セレクタ（Selectors）
        * [NW_R7_PM2_問2](https://www.ipa.go.jp/shiken/mondai-kaiotu/nl10bi0000009lh8-att/2025r07h_nw_pm2_qs.pdf) p16
  * SA（Security Association）
    * 参考：[IPsec - SA ( Security Association )](https://www.infraexpert.com/study/ipsec7.html)
    * 概念的には、IPsecにおいて、通信する2者間で使用する暗号化アルゴリズムなどの取り決めのこと
    * 実質的には、IPSecのパラメータのセット（以下）
      * SPIの値
      * 通信モード：トンネルモード/トランスポートモード
      * プロトコル：ESP/AH
      * 暗号化方式：DES/3DES/AES
      * 上記の暗号鍵
      * 認証：HMAC-MD5/SHA1
      * 認証鍵
      * シーケンス番号カウンタ
      * DSCP値
      * Path MTU
      * トンネルエンドポイントのIPアドレス
      * SAのライフタイム
    * **SPI**（Security Parameters Index）
      * 複数のSAを作成・使用するため、SAを識別するためのキー
      * 32bitの値で、[AHやESPパケットフィールド](infraexpert.com/study/ipsec5.html)に設定される
    * SAD（SA Database）
      * IPSecルータが保存するSAのローカルDB
  * IKE（Internet Key Exchange）：SAを作るためのプロトコル。IKEv1、IKEv2がある
    * IKE v1
      * [NW_H28_PM2_問2](https://www.ipa.go.jp/shiken/mondai-kaiotu/gmcbt8000000g6fw-att/2016h28a_nw_pm2_qs.pdf)のp14〜16が詳しい
  * ESP（Encapsulating Security Payload）、AH（Authentication Header）：通信データの暗号化のプロトコル
* IPSec NATトラバーサル
  * [NW_H27_PM2_2](https://www.ipa.go.jp/shiken/mondai-kaiotu/gmcbt8000000gxj0-att/2015h27a_nw_pm2_qs.pdf) p15,16 \[IPsecを利用する顧客への対応策\]

# IEEE802.1x
無線/有線LANに関わらず、ポートごとに認証を行い、認証に成功した端末だけがLANに接続できるようにするためのプロトコル/規格。
要は、LAN内での接続相手を認証を通すことで制限する仕組み。
* システム構成
  * サプリカント(supplicant)
  * オーセンティケータ(authenticator)
  * 認証サーバ
* 認証プロトコル
  * **EAP**(Extensible Authentication Protocol)
    * PPPの拡張プロトコル
    * IEEE802.1xの認証で用いられる
    * 認証方式がいくつかある
      * **EAP-MD5**
        * クライアント認証にユーザ名とパスワードを使用
        * パスワードは平文では送らず、CHAP同様にハッシュ関数MD5でハッシュ化する
        * サーバ認証は行わない
      * **EAP-TLS**
  * **EAPOL**(EAP Over LAN)
    * サプリカント-オーセンティケータ間でEthernetを使用している場合の、EAPパケットをEthernet上でやり取りするためのプロトコル
    * EAPパケットにEAPOLヘッダを付けてEthernetフレームにカプセル化される
    * オーセンティケータは受け取ったEAPパケットをRADIUSパケットに乗せ替えて転送する
