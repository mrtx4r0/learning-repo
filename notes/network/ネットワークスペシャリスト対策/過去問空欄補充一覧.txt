ネットワークスペシャリスト
午後Ⅰ・午後Ⅱ 空欄補充用語＋関連知識
平成24年度～令和7年度

【使い方】

「用語」
→ 問題文で出てきたヒント
→ その用語が意味するもの
→ 一緒に思い出す関連知識

単語だけを暗記するのではなく、
「この説明なら、この用語」
「この用語なら、この関連知識」
まで連想できる状態を目指す。

==================================================
■ 平成24年度

【ゾーン】
→ DNSで「ドメインの権限をどこが管理するか」という話
→ DNSにおける管理単位。
→ ゾーンを別のDNSサーバへ委譲できる。
→ 「権威DNS」「ゾーン委譲」「NSレコード」とセット。

【権威】
→ DNS-Sなどが、あるドメインについて正式な情報を管理している
→ 権威DNSサーバ。
→ キャッシュDNS（フルサービスリゾルバ）とは役割が違う。
→ 「ゾーン」「委譲」「NSレコード」とセット。

【SPOF / Single Point of Failure】
→ その箇所が故障すると、全体のサービス継続ができなくなる
→ 単一障害点。
→ 冗長化することでSPOFをなくす。
→ 「冗長化」「Active/Standby」「負荷分散」とセット。

【エッジポート】
→ ルーティングブリッジで、末端機器につながるポート
→ エンド端末側のポート。
→ 他のブリッジとのループを形成しないことを前提にする。
→ 「IEEE 802.1Q」「VLAN」「トランク」と混同しない。

【IEEE 802.1Q】
→ VLAN IDをフレームに付加してVLANを識別する規格
→ VLANタグ。
→ タグ付きフレームを使って複数VLANを1本のリンクに通す。
→ 「トランクポート」「VLAN ID」「タグVLAN」とセット。

【FCoE / FCoEフレーム】
→ データセンターでLANとSANを統合する話
→ Fibre Channel over Ethernet。
→ FCフレームをEthernet上で運ぶ。
→ 「FCoEフレーム」「FCフレーム」「FCF」「HBA」「SAN」とセット。

【HC】
→ ルーティングブリッジで「最小ホップ数以外の経路も障害時に使いたい」
→ Hop Count。
→ 経路のホップ数を基準にする。
→ 冗長経路を持たせることで障害時の代替経路を確保。

平成24年度午後ⅠではDNSの「ゾーン」「権威」など、午後Ⅱではデータセンターの「SPOF」「IEEE 802.1Q」「FCoE」などが登場。問題文の「DNSの権限」「データセンター」「LANとSANの統合」といった言葉をトリガーにする。(IPA)

■ 平成25年度

【HELLO】
→ SSL-VPN装置などが接続相手との状態確認を行う
→ 隣接関係を維持・確認するためのメッセージ。
→ OSPFなどでもHelloという名前が使われるので、プロトコルを問題文から判断する。

【FQDN】
→ サーバを「完全なドメイン名」で指定する
→ Fully Qualified Domain Name。
→ ホスト名＋ドメイン名。
→ DNS名前解決とセット。

【第三者認証局 / CA】
→ 「クライアント証明書」「証明書の有効性」「信頼された認証」
→ 第三者認証局が証明書を発行。
→ 認証局の公開鍵を信頼することで証明書を検証する。

【L3SW / レイヤ3スイッチ】
→ VLAN間通信、IPルーティングを行うスイッチ
→ L2SWとの違いは、IP層でルーティングすること。
→ 「SVI」「デフォルトゲートウェイ」「VLAN間ルーティング」とセット。

【802.11】
→ 無線LANの標準規格
→ IEEE 802.11。
→ 問題文に「無線LANの最初の標準規格」などが出た場合に反応。
→ 802.11b/g/a/n/ac/axなどの世代・拡張規格へつながる。

【暗号化】
→ 無線LANで「電波を盗聴されても内容を読めなくする」
→ データを暗号化する。
→ 認証とは別概念。
→ 「IEEE 802.1X」「WPA」「WPA2」「WPA3」などと関連。

【RC4】
→ 古い無線LANの暗号方式
→ ストリーム暗号。
→ WEPや初期のWPAで使用された。
→ 現在は安全性の問題から使用しない。

【ESSID / SSID】
→ 無線LANで「どのネットワークに接続するか」を識別
→ SSIDは無線LANのネットワーク識別子。
→ ESSIDは拡張されたSSIDという歴史的表現。
→ 「AP」「ローミング」「無線LAN」とセット。

【GARP / Gratuitous ARP】
→ モバイルIPや冗長化などで「自分のIPとMACの対応を周囲に更新させる」
→ Gratuitous ARP。
→ ARP Request/Replyの通常の名前解決とは目的が違う。
→ 「ARPキャッシュ更新」「VIP」「フェイルオーバー」とセット。

【プロキシARP】
→ 自分自身宛てではないARP要求に代理で応答
→ ルータなどが通信相手の代わりにMACアドレスを返す。
→ 「同一サブネットだと思わせる」「ARP」とセット。

【HA / Home Agent】
→ モバイルIPで移動端末のホームネットワーク側を担当
→ Home Agent。
→ FA（Foreign Agent）と対になる。

【FA / Foreign Agent】
→ モバイルIPで訪問先ネットワーク側を担当
→ Foreign Agent。
→ HAと組み合わせてモバイルIPを理解する。

平成25年度は特に無線LANとモバイルIPが重要。「無線LANの標準規格」「SSID」「暗号化」「ローミング」「ARPキャッシュ」などが問題文のトリガー。IPAの採点講評でも802.11、暗号化、RC4、SSIDに相当する部分の正答率が低かったとされています。(IPA)

■ 平成26年度

【帯域幅】
→ ネットワークで「どれだけの通信量を流せるか」
→ 通信容量。
→ 「通信速度」「スループット」と似るが同一ではない。

【TOS】
→ IPヘッダでサービス品質・優先制御に関係するフィールド
→ Type of Service。
→ IPv4ではDSCP/ECNへ発展。
→ 「QoS」「DiffServ」とセット。

【DiffServ / Differentiated Services】
→ IPパケットをクラス分けしてQoS制御
→ DSCP値などを使って優先度を扱う。
→ 「TOS」「DSCP」「QoS」とセット。

【VRRP】
→ デフォルトゲートウェイを冗長化
→ Virtual Router Redundancy Protocol。
→ 仮想IPアドレスを複数ルータで共有。
→ プライオリティ値によってMasterを選ぶ。
→ 「仮想ルータ」「Master/Backup」「デフォルトゲートウェイ」とセット。

【NAPT】
→ 複数のプライベートIPを1つのグローバルIPで外部通信
→ IPアドレスだけでなくTCP/UDPポート番号も変換。
→ 「NAT」「PAT」「ポート番号」「変換テーブル」とセット。

【ステートフル】
→ FWが「通信の状態」を保持して戻り通信を判断
→ TCPコネクションなどの状態を追跡。
→ 「ステートレス」「FW」「セッション」と対比。

【Gratuitous ARP / GARP】
→ IPアドレスとMACアドレスの対応を周囲に更新させる
→ ARPキャッシュ更新。
→ 冗長化・VIP切替で頻出。

【タグ / Tag】
→ EthernetフレームにVLAN識別情報を付ける
→ IEEE 802.1Qタグ。
→ 「アクセスポートでは通常タグなし」「トランクでは複数VLANをタグで識別」と関連。

【MACアドレステーブル】
→ L2スイッチが「MACアドレスとポートの対応」を学習
→ 受信フレームの送信元MACから学習。
→ 宛先MACを見て出力ポートを決定。
→ 不明な宛先ならフラッディング。
→ 「ARPテーブル」と混同しない。

【分散】
→ DDoSなどで「大量の送信元から攻撃」
→ Distributed。
→ 「DDoS」「ボットネット」「踏み台」と関連。

【フラッド】
→ 大量の通信を送りつける
→ Flood。
→ 「DDoS」「帯域圧迫」「リソース枯渇」と関連。

【再帰】
→ DNSサーバがクライアントの代わりに別DNSへ問い合わせる
→ Recursive Query。
→ 「フルサービスリゾルバ」「キャッシュDNS」とセット。

【リフレクタ】
→ DNSなどで送信元を偽装し、第三者から攻撃対象へ大量の応答を返させる
→ 反射型DDoS。
→ 「DNS」「オープンリゾルバ」「増幅攻撃」とセット。

【ペネトレーション】
→ セキュリティ対策の有効性を実際の攻撃に近い形で検証
→ ペネトレーションテスト。
→ 「脆弱性診断」とは目的・方法が異なる。

平成26年度は「NAPT・ステートフル・GARP・VLANタグ」といった基本ネットワーク用語と、「DNS・DDoS」のセキュリティ用語がまとまって出題されている。(IPA)

■ 平成27年度

【リバースプロキシ】
→ Webサーバの手前に置き、クライアントからのアクセスを代理受信
→ Webサーバ側の代理。
→ 「フォワードプロキシ」はクライアント側の代理。
→ 「負荷分散」「SSL終端」「キャッシュ」と関連。

【リダイレクト】
→ HTTP通信で「別URLへ移動させる」
→ 3xx応答などでブラウザに別URLへのアクセスを指示。
→ 「Locationヘッダ」「HTTP」と関連。

【Set-Cookie】
→ HTTPレスポンスでCookieをクライアントへ設定
→ 次回以降のリクエストでCookieが送られる。
→ 「セッション維持」「ロードバランサ」「Secure属性」と関連。

【内部DNS】
→ 社内向けの名前解決を行うDNS
→ 外部DNSとは役割・公開範囲が違う。
→ 「内部向けゾーン」「split DNS」と関連。

【ループバック】
→ サーバ自身を指す特殊なインタフェース
→ 127.0.0.0/8など。
→ ロードバランサのDSR方式でも重要。

【GARP】
→ DSR方式のLBなどでVIP/MAC情報を更新
→ Gratuitous ARP。
→ 「VIP」「ARPキャッシュ」「負荷分散」とセット。

【M2M】
→ 機器同士が人を介さず通信
→ Machine to Machine。
→ IoTの先行概念。
→ 「センサ」「設備」「稼働情報」と関連。

【CoAP】
→ IoTなどの制約された機器向けWeb系プロトコル
→ Constrained Application Protocol。
→ UDPを使用。
→ TCPの接続確立・切断が不要。
→ HTTPと似たREST的な通信が可能。
→ 「IoT」「UDP」「軽量」「REST」とセット。

【中継装置】
→ M2Mシステムで設備と通信アダプタの間に存在
→ データを中継・集約する装置。

【通信アダプタ】
→ 設備側で通信を担当する装置
→ 稼働情報などを収集・送信。
→ キャッシュを持つ構成もある。

平成27年度午後Ⅱでは、M2M→HTTP/TCP→CoAP/UDPという「通信方式の違い」が一連の流れで問われた。CoAPを見たら「UDP」「TCPコネクション不要」「軽量ヘッダ」を連想する。(IPA)

■ 平成28年度

【MX】
→ DNSで「メール配送先」を指定
→ Mail Exchange。
→ DNSのMXレコード。
→ 「SMTP」「メールサーバ」「優先度」とセット。

【SMTP-AUTH】
→ SMTPで送信者を認証
→ メール送信時の認証。
→ OP25B対策やSubmissionポートと関連。

【サブミッションポート】
→ メールクライアントからメールサーバへ送信するためのポート
→ 代表的にTCP 587。
→ SMTPのTCP 25番はサーバ間配送で利用される。
→ 「SMTP-AUTH」「OP25B」「587」とセット。

【MAIL FROM】
→ SMTP通信で送信者アドレスを指定
→ SMTPコマンド。
→ 「RCPT TO」「DATA」とセット。

【WebRTC】
→ Webブラウザ同士などでリアルタイム通信
→ Web Real-Time Communication。
→ 音声・映像・データ通信。
→ 「STUN」「SIP」「WebSocket」と関連。

【SIP】
→ IP電話などの呼制御
→ Session Initiation Protocol。
→ 「REGISTER」「INVITE」「200 OK」「RTP」「SDP」とセット。

【STUN】
→ NAT配下の端末が自分のグローバル側のアドレス・ポートを知るために使用
→ WebRTCなどで利用。
→ 「NAT traversal」「ICE」とセット。

【WebSocket】
→ HTTPのUpgradeなどを利用して双方向通信を確立
→ 一度接続するとサーバ・クライアント双方からデータ送信可能。
→ 「リアルタイム通信」「HTTP」「TCP」とセット。

【切り戻し】
→ 新システムへの移行後、問題があったため旧構成へ戻す
→ ロールバック。
→ 「移行」「切替」「障害」「復旧」とセット。

【HTTP】
→ Web通信のアプリケーション層プロトコル
→ WebSocket、WebRTC、RESTなどと関連。

【UDP】
→ コネクションレス型トランスポート
→ TCPのような接続確立・再送制御をプロトコル自身では行わない。
→ VoIP、DNS、WebRTCなどで利用。

平成28年度はメール、WebRTC、SIP、NAT traversalなどが連続して出てくる。「メール送信」「リアルタイム通信」「NAT越え」がトリガー。(IPA)

■ 平成29年度

【SHA-1】
→ TLS/SSLでハッシュアルゴリズムとして登場
→ 古いハッシュ関数。
→ 現在の安全な設計ではSHA-256系などを使う。
→ 「ハッシュ」「メッセージ認証」と関連。

【TLS 1.2】
→ SSL-VPNやHTTPSの暗号通信
→ TLSのバージョン。
→ 「Client_Hello」「Server_Hello」「暗号スイート」「証明書」とセット。

【Client_Hello】
→ TLSハンドシェイクでクライアントが最初に送るメッセージ
→ TLSバージョン、乱数、利用可能な暗号スイートなどを提示。

【Server_Hello】
→ TLSサーバ側が応答
→ 使用するTLSバージョンや暗号スイートなどを決定。

【リバースプロキシ】
→ Webサービスの手前に配置
→ サーバ側を代理。
→ 「TLS終端」「負荷分散」「DMZ」と関連。

【鍵交換】
→ TLSで通信に使う鍵を安全に合意
→ 公開鍵暗号などを利用。
→ 「認証」「共通鍵」「暗号化」とセット。

【認証】
→ 通信相手が誰であるか確認
→ TLSではサーバ証明書によるサーバ認証など。

【メッセージ認証】
→ 通信内容が改ざんされていないか、正当な送信元からのものか確認
→ MAC/HMACなどと関連。

【vNIC】
→ 仮想マシンに見える仮想ネットワークインタフェース
→ Virtual Network Interface Card。
→ 「仮想スイッチ」「仮想マシン」「ハイパーバイザ」と関連。

【DMZ】
→ インターネット公開サーバなどを内部LANから分離して置くネットワーク
→ 「FW」「内部LAN」「公開サーバ」とセット。

【Flow-Mod】
→ OpenFlowでフローエントリを追加・変更する指示
→ SDNコントローラからスイッチへ送信。

【Packet-Out】
→ OpenFlowコントローラからスイッチへ、特定パケットを処理・送信させる
→ Flow-Modとは役割が違う。

【controller】
→ SDNでネットワーク機器を集中制御する装置・ソフトウェア
→ 「OpenFlow」「Flow-Mod」「Packet-Out」「OFS」とセット。

【OFS】
→ OpenFlow Switch
→ コントローラから指示を受けてパケット転送。

【CNAME】
→ DNSの別名レコード
→ ある名前を別の正規名へ向ける。
→ 「A/AAAA」「DNS」「名前解決」とセット。

【CDN】
→ Content Delivery Network
→ 利用者に近い配信拠点からコンテンツを配信。
→ 「キャッシュ」「負荷分散」「DDoS対策」と関連。

【IaaS】
→ Infrastructure as a Service
→ 仮想マシン、ネットワーク、ストレージなどの基盤をサービスとして提供。
→ 「SaaS」「PaaS」と比較。

平成29年度は「SSL-VPN」「SDN」「OpenFlow」「クラウド」が非常に重要。特にFlow-Mod / Packet-Out / controllerは、単語単体ではなく「controller → OpenFlow → OFS」という向きを覚える。(IPA)

■ 平成30年度

【フォワード】
→ フォワードプロキシ
→ クライアント側の代理として外部Webへアクセス。
→ 「リバースプロキシ」と対比。

【リバース】
→ リバースプロキシ
→ サーバ側の代理。
→ 「ロードバランサ」「TLS終端」「Webサーバ」と関連。

【CONNECTメソッド】
→ HTTPプロキシ経由でHTTPS通信を行う
→ プロキシに「指定先とのTCPトンネルを確立してほしい」と要求。
→ HTTPSの暗号化された内容自体をプロキシが通常読めるわけではない。
→ 「HTTP CONNECT」「プロキシ」「TLS」とセット。

【プロキシサーバのルート証明書】
→ プロキシがHTTPS通信を中間で復号・検査する構成
→ クライアント側がプロキシ発行の証明書を信頼するために必要。
→ 「SSL/TLSインターセプト」「中間者」「証明書」と関連。

【コントロール】
→ SD-WANなどで制御情報を扱う
→ データ転送そのものではなく制御プレーン側。
→ 「SDN」「SD-WANコントローラ」と関連。

【SD-WANコントローラ】
→ SD-WANルータなどを集中制御
→ 経路・ポリシーなどを集中管理。
→ 「コントロールプレーン」「SD-WANルータ」とセット。

【暗号化】
→ MQTTなどのIoT通信を保護
→ 「TLS」「VPN」と関連。

【検知】
→ セキュリティ機器が異常を発見
→ IDS/IPSなどと関連。

【認証】
→ クライアント証明書などを使って通信主体を確認
→ 「認可」と区別。
→ 認証＝誰か、認可＝何をしてよいか。

【SUBSCRIBE】
→ MQTTで特定トピックのメッセージを購読
→ Publisher → Broker → Subscriberというモデル。
→ 「MQTT」「PUBLISH」「Broker」「Topic」とセット。

【WebAP】
→ Web Application
→ HTTP等を受けてアプリケーション処理を行う。
→ 「認可」「URI」「Webサーバ」と関連。

【リフレッシュトークン】
→ OAuth系の認証・認可でアクセストークンを再取得するためのトークン
→ 「アクセストークン」「認可サーバ」とセット。

平成30年度は「プロキシ」「SD-WAN」「MQTT」「認可」がポイント。特にCONNECTを見たら「HTTPプロキシでHTTPSのトンネルを作る」と連想する。(IPA)

■ 令和元年度（平成31年度）

【BGP / BGP4】
→ AS間で経路交換
→ Border Gateway Protocol。
→ 「AS」「ピア」「UPDATE」「KEEPALIVE」「TCP 179」とセット。

【バックボーン】
→ 大量の通信を集約するネットワークの中核部分
→ 「コアネットワーク」「L3SW」「ルータ」と関連。

【GARP】
→ LAGや冗長化などでMAC情報を更新
→ Gratuitous ARP。

【ICMP】
→ IP層の制御・エラー通知
→ PingのEcho Request/Replyなど。
→ 「IP」「死活監視」とセット。

【SNMPトラップ】
→ 監視対象機器から管理サーバへ異常などを自発的に通知
→ ポーリングとは逆方向の発想。
→ 「SNMP Manager」「SNMP Agent」「MIB」とセット。

【MIB】
→ SNMPで管理対象となる情報の定義
→ Management Information Base。
→ 「OID」「SNMP Agent」と関連。

【IP-PBX】
→ IPネットワーク上で電話交換機能を提供
→ 「SIP」「REGISTER」「RTP」「VoIP」とセット。

【REGISTER】
→ SIP端末がSIPサーバへ自分の現在位置・連絡先を登録
→ SIPの代表的なメッセージ。

【SIP UA】
→ SIP User Agent
→ SIP通信を行う端末側。
→ IP電話機、ソフトフォンなど。

【200 OK】
→ SIPで要求が正常に処理されたことを示す成功応答
→ HTTPの200 OKと似たステータスコード体系を持つが、SIPの応答。

【MPLS】
→ Multi-Protocol Label Switching
→ ラベルを使って高速・柔軟にパケットを転送。
→ 「MPLS-VPN」「PE」「CE」と関連。

【フルメッシュ】
→ 拠点間をすべて相互接続
→ 冗長性は高いが、接続数が増える。
→ 「ハブアンドスポーク」「VPN」と対比。

【Y-BBR】
→ 問題文中の特定のWANサービス・装置
→ 単語だけでなく、図中の経路と組み合わせて読む。

令和元年度は「LAG」「BGP」「SNMP」と「クラウドPBX/SIP」が中心。SIPについてはREGISTER → 200 OK → RTP → SDPという通信の流れまで連鎖させる。(IPA)

→ 「DHCPリレー」「giaddr」と関連。

【SNMP】
→ ネットワーク機器を監視・管理
→ Manager / Agent / MIB / Trap。
→ 「ポーリング」「トラップ」とセット。

【RT管理コントローラ】
→ ネットワーク機器の設定を集中管理
→ 自動化・運用管理。
→ 「API」「コントローラ」「設定自動化」と関連。

【フォワーダ】
→ DNSでフルサービスリゾルバへ問い合わせを転送
→ DNS Forwarder。
→ 「DNSキャッシュ」「フルサービスリゾルバ」とセット。

【プライオリティ値】
→ VRRPでMasterルータを選ぶ
→ 値が大きいルータが優先。
→ 「VRRP」「仮想IP」「Master/Backup」とセット。

【指定】
→ STP/RSTPの指定ポート
→ セグメントごとにルートブリッジへ向かう代表的なポート。
→ 「非指定」「ルートポート」「BPDU」と関連。

【非指定】
→ STPでループを防ぐため、フレーム転送を行わないポート
→ RSTPではDiscardingなど状態遷移と関連。
→ 「指定ポート」「ルートブリッジ」とセット。

【MACアドレス】
→ STPトポロジ変更時にMACアドレステーブルが影響を受ける
→ L2スイッチが学習する転送情報。
→ 「MACアドレステーブル」「フラッディング」とセット。

【上位のスイッチ】
→ RSTPで「どちらが優先されるスイッチか」を判断
→ ブリッジIDやパスコストなどから上位・下位を決める。

【スタック】
→ 複数の物理スイッチを論理的に1台として管理
→ 運用・設定を簡素化。
→ 「リンクアグリゲーション」「冗長化」と関連。

【リンクアグリゲーション】
→ 複数の物理リンクを論理的に1本として利用
→ 帯域向上・冗長化。
→ LAG / LACPと関連。

令和3年度は「DNSフォワーダ」「VRRP」「STP/RSTP」「スタック」「LAG」が一連で登場。特にSTP系は「指定/非指定/ルートブリッジ/MACアドレステーブル」を一まとまりにする。(IPA)

【LDAPサーバ】

【フラッディング】

【制御サーバ】

【プロミスキャス】

【改ざん検知】

【L2フォワーディング】

【ポートフォワーディング】

【DHE】

→ 前方秘匿性（Forward Secrecy）と関連。

【Subject】

→ 証明書の「誰についての証明書か」を表す。
→ 「Issuer」「CA」と対比。

■ 令和5年度

【リバース】
→ リバースプロキシ
→ Webサーバ側の代理。
→ 「HTTP」「Webサーバ」「負荷分散」と関連。

【権威】
→ 権威DNS
→ そのゾーンについて正式なDNS情報を持つ。
→ 「キャッシュDNS」「ゾーン」「NS」と関連。

【キャッシュ】
→ DNSキャッシュ
→ 過去の名前解決結果を一時保存。
→ TTLが切れるまで保持。
→ 「キャッシュDNS」「TTL」「権威DNS」とセット。

【ストリーム】
→ HTTP/2で論理的な通信単位
→ 1本のTCP接続上に複数ストリームを多重化。
→ 「HTTP/2」「ストリームID」「多重化」とセット。

【:method】
→ HTTP/2のヘッダフィールド
→ HTTP/1.1のMethodに相当する情報。
→ 「:path」「:scheme」「:authority」などの擬似ヘッダと関連。

【TLS】
→ HTTP/2の下位で利用
→ 暗号化・認証・完全性。
→ 「HTTPS」「ALPN」「TLSハンドシェイク」と関連。

【AS】
→ Autonomous System
→ 一つの管理主体のもとで経路制御されるネットワークの集合。
→ BGPがAS間の経路交換に使用。

【ピア】
→ BGPで経路交換する相手ルータ
→ BGP Peer。
→ 「TCP 179」「eBGP/iBGP」と関連。

【UPDATE】
→ BGPで経路情報の追加・削除を通知
→ BGPの主要メッセージ。
→ 「AS」「ピア」「KEEPALIVE」とセット。

【KEEPALIVE】
→ BGPピア間で接続維持を確認
→ 一定時間受信できなければHold Timer満了につながる。
→ 「UPDATE」「NOTIFICATION」「TCP 179」とセット。

【ルーティングテーブル】
→ 実際にパケット転送時に参照する経路情報
→ 宛先ネットワークとネクストホップ等を保持。
→ 「BGP」「OSPF」「静的経路」と関連。

【大きい】
→ BGPのLOCAL_PREFで最適経路を選ぶ
→ LOCAL_PREFは値が大きい経路を優先。
→ MEDは小さい方を優先するので混同注意。

令和5年度は「HTTP/2」と「BGP」が非常に典型的。「ストリーム」を見たらHTTP/2、「AS・ピア・UPDATE・KEEPALIVE」を見たらBGPを即座に連想する。(IPA)

■ 令和6年度

【最少接続数】
→ ロードバランサの負荷分散方式
→ 現在の接続数が最も少ないサーバへ振り分ける。
→ 「ラウンドロビン」「最少応答時間」などと対比。

【LB】
→ Load Balancer
→ 複数サーバへ通信を振り分ける。
→ 「ヘルスチェック」「最少接続数」「CDN」と関連。

【IX】
→ Internet eXchange
→ 異なるISP/AS間でトラフィックを交換する接続拠点。
→ 「BGP」「AS」「ピアリング」とセット。

【BGP】
→ AS間の経路交換
→ 「AS」「ピア」「UPDATE」「KEEPALIVE」「TCP 179」。

【VXLAN】
→ データセンターでL2ネットワークをL3ネットワーク上に仮想的に延伸
→ VXLAN Network Identifier（VNI）を使用。
→ UDP 4789を使用。
→ 「VTEP」「VNI」「EVPN」とセット。

【VTEP】
→ VXLAN Tunnel Endpoint
→ VXLANトンネルの入口・出口。
→ EthernetフレームをVXLANでカプセル化/解除。
→ 「VNI」「VXLANヘッダ」「UDP」とセット。

【VXLANヘッダー】
→ EthernetフレームをVXLANでカプセル化すると付加
→ VNIを含む。
→ 外側にはUDP/IP/Ethernetヘッダーが付く。

【LSDB】
→ OSPFのリンク状態データベース
→ Link State Database。
→ ネットワークトポロジ情報を保持。
→ SPF計算で最短経路を求める。
→ 「LSA」「SPF」「OSPF」とセット。

【最短経路】
→ OSPFでLSDBから計算
→ SPFアルゴリズム。
→ コストの合計が小さい経路を選択。

【Unknown Unicast】
→ 宛先MACアドレスをVTEPなどが知らない
→ 宛先が不明なユニキャスト。
→ VXLAN/EVPNでBUMトラフィックの扱いと関連。

【ESI】
→ Ethernet Segment Identifier
→ EVPNでマルチホーム構成のEthernet Segmentを識別。
→ 「EVPN」「ESI」「マルチホーム」とセット。

【クラスターID】
→ BGP Route Reflectorでクラスターを識別
→ iBGPのフルメッシュを減らすための仕組み。
→ 「Route Reflector」「iBGP」「クラスタ」とセット。

【MP-BGP】
→ Multiprotocol BGP
→ IPv4以外のアドレスファミリなどもBGPで扱う拡張。
→ EVPNの経路情報交換にも利用。

令和6年度午後Ⅱは「VXLAN → VTEP → VNI → EVPN → MP-BGP」というデータセンター系の知識連鎖が重要。OSPFについても「LSDB → LSA → SPF → 最短経路」という流れで覚える。(IPA)

■ 令和7年度

【プライベート】
→ 内部ネットワークで使用するIPアドレス
→ IPv4ではRFC 1918のプライベートアドレス。
→ NAPTなどでグローバルIPへ変換して外部通信。

【グローバル】
→ インターネット上で一意に扱うIPアドレス
→ プライベートIPと対比。
→ 「NAPT」「NAT」「インターネット」とセット。

【PoE+】
→ Ethernetケーブルから電力を供給
→ IEEE 802.3at。
→ PoE（802.3af）の拡張。
→ PoEより大きな電力を供給可能。
→ 無線LANアクセスポイントなどで利用。
→ 「PSE」「PD」「PoE」「IEEE 802.3」とセット。

【帯域確保】
→ ネットワーク上で必要な通信量を確保
→ QoSなどで重要。
→ 「帯域」「トラフィック」「優先制御」と関連。

【リクエスト】
→ HTTPでクライアントからサーバへ送る要求
→ Request。
→ 「レスポンス」「HTTP」「HTTP/2」「ストリーム」とセット。

【レスポンス】
→ HTTPでサーバからクライアントへ返す応答
→ Response。
→ 「リクエスト」と対になる。

【ストリームID】
→ HTTP/2で各ストリームを識別
→ 1本のTCP接続上に複数のストリームを多重化。
→ 「HTTP/2」「リクエスト」「レスポンス」「多重化」とセット。

【並列】
→ HTTP/2で複数のストリームを同時に処理
→ HTTP/1.1で問題になったHead-of-Line Blockingとの関係を意識。
→ 「ストリーム」「多重化」とセット。

【GUA】
→ Global Unicast Address
→ IPv6のグローバルユニキャストアドレス。
→ インターネットなどで使用。
→ 「LLA」「プレフィックス長」「SLAAC」「RA」とセット。

【デフォルトルータ】
→ IPv6で外部ネットワークへパケットを送る際の次のルータ
→ IPv4のデフォルトゲートウェイに相当。
→ RAで通知される。
→ 「ICMPv6」「RS」「RA」とセット。

【TCP】
→ コネクション型トランスポート
→ 信頼性・順序制御・再送などを提供。
→ 「HTTP」「FQDN」「DNS」と関連。

【FQDN】
→ 完全修飾ドメイン名
→ DNS名前解決の対象。
→ 「A/AAAA」「権威DNS」「DNSサーバ」とセット。

【NAPT】
→ IPv4のプライベートアドレス＋ポート番号をグローバル側へ変換
→ 多数の内部端末が少数のグローバルIPを共有。
→ 「変換テーブル」「TCP/UDPポート」とセット。

【宛先IPアドレス】
→ IPv6などで「どこへ送るか」を判断
→ ルータは宛先IPを見て経路選択。

【ブロード】
→ ブロードキャスト
→ 同一ネットワーク内の全ノードを対象。
→ IPv6ではIPv4のようなブロードキャストを使用せず、マルチキャストを利用。

【リプライ】
→ ICMP Echo Replyなどの応答
→ 「Echo Request」と対になる。

令和7年度は午後Ⅰで「プライベート/グローバル/PoE+」、HTTP/2の「リクエスト/レスポンス/ストリームID/並列」が出題。午後ⅡではIPv6の「GUA/デフォルトルータ」などが空欄として登場。(IPA)
